# Repo Runner

Run GitHub repos on an Android phone. Paste a link, and the app clones the repo, works out what it needs (Node, Bun, Python, Go, Rust…), installs it, starts it, and shows it in a built-in preview.

## How it works

```
React Native UI (src/app)          screens: home, project, terminal, preview
        │
State (src/state/RunnerContext)    projects, run phases, logs, detected port
        │
Runtime plugins (src/runtimes)     detect a repo → plan install / deps / start
        │
Native module (modules/runner)     Kotlin: download Debian, run proot, stream output
        │
proot + Debian arm64               real Linux userland, no root needed
```

- **proot** runs a full Debian system inside the app's private storage. The binaries ship inside the APK as `lib*.so` files so Android lets the app execute them (Android 10+ blocks running files the app downloads itself).
- **Debian** is downloaded on first launch from the [proot-distro](https://github.com/termux/proot-distro) releases (about 30 MB), then `git`, `curl` and a few basics are installed.
- **Runtimes are installed on demand** by the plugin that matches the repo, then reused across projects.

## Project layout

| Path | What it is |
| --- | --- |
| `src/app/` | Expo Router screens |
| `src/state/RunnerContext.tsx` | App state and the run pipeline (runtime → deps → start) |
| `src/core/bootstrap.ts` | First-run Linux setup |
| `src/core/projects.ts` | Cloning and saving projects |
| `src/core/sessions.ts` | Starting / stopping processes, output events |
| `src/core/ports.ts` | Finds the dev-server URL in the logs |
| `src/runtimes/` | One file per language + `registry.ts` |
| `src/runtimes/shell.ts` | `/opt/runner/lib.sh` helpers (`node_use`, `bun_use`, `apt_need`…) and the Android network fix for Node |
| `src/core/github.ts` | GitHub sign-in (device flow or token), repo list |
| `src/terminal/` | xterm.js page for the terminal (assets generated by `npm run gen-terminal`) |
| `modules/runner/` | Local Expo native module (Kotlin + a small C file for the PTY) |
| `scripts/fetch-binaries.sh` | Downloads proot for arm64 into the native module |

## Adding a language

1. Create `src/runtimes/<name>.ts` exporting a `RuntimePlugin` with `detect()` and `plan()`.
2. If it needs a new installer, add a `<name>_use` function to `RUNNER_LIB` in `shell.ts`.
3. Add it to `PLUGINS` in `src/runtimes/registry.ts`.

Highest `confidence` wins. The user can switch when several plugins match.

## Building

This needs a development build; it won't run in Expo Go.

```bash
npm install

# Option A – EAS (cloud build, works from Windows). The proot binaries are
# fetched automatically by the eas-build-pre-install script.
npx eas-cli@latest build --profile development --platform android

# Option B – local build (Linux, macOS or WSL with Android SDK)
npm run fetch-binaries
npx expo run:android
```

Then `npm start` and open the app on your phone.

Requirements: a 64-bit ARM Android phone (almost every phone from the last few years), Android 7+.

## Terminal

The terminal is a real one: a login shell on a pseudo-terminal (`modules/runner/android/src/main/cpp/pty.c`), drawn by xterm.js in a WebView. `vim`, `nano`, `htop`, colours and interactive prompts work. The key bar adds Esc, Ctrl (tap, then a letter), Tab, arrows and ^C.

## Running in the background

While anything runs (a dev server, an install, a terminal), a foreground service shows a "Running …" notification and holds a wake lock, so Android doesn't stop your servers when you switch apps. The notification has a **Stop all** button. On Android 13+ the app asks once for notification permission.

## Private repos

Tap **GitHub** on the home screen.

- **Paste a token** (always available): create a personal access token with the `repo` scope and paste it.
- **Sign in with GitHub** (optional, nicer): create an OAuth App at github.com → Settings → Developer settings → OAuth Apps, tick **Enable Device Flow**, and put its Client ID in `app.json` → `expo.extra.githubClientId`. No client secret is needed.

The token is kept in the Android Keystore (expo-secure-store). Inside Linux, git gets it only through a credential helper that reads an environment variable, so it is never written to disk there. `git clone`, `git pull` and `git push` to github.com all work, in the app and in the terminal. Once signed in, **Your repos** lists your repos, private ones included.

## Security model

- **Repos are untrusted code.** Install scripts and dev servers run inside the Linux environment as the app's own Android user. They can't reach your other apps or your photos and files, but they can read and change anything inside Repo Runner, including your other projects. Only run repos you trust.
- **Your GitHub token is kept away from repo code.** Only cloning and the terminal get it; install and run steps never see it. Anything you run yourself in the terminal could still read it.
- **Deleting is link-safe.** Project deletion removes symbolic links instead of following them, and the app refuses to delete anything outside `/root/projects` and its own data folder.
- **Downloads are checked.** The Linux image is verified against the SHA-256 GitHub publishes for it, Node.js against nodejs.org's checksums, and the proot packages against the Termux package index.

## Known limits

- **ARM only.** Packages that only ship x86 binaries won't run. Docker isn't possible.
- **Battery.** Long-running servers with a wake lock use battery; stop them from the notification when done.
- **First runs are slow.** Installing Node + `npm install` on a phone can take a few minutes; later runs skip the install.
- **Only github.com** gets automatic sign-in; other git hosts still work for public repos.
